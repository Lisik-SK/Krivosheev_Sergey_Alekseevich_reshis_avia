# Решись Авиа

Веб-приложение для прогноза продаж авиабилетов. Менеджер выбирает города, дату и цену билета, а приложение показывает ожидаемый спрос, загрузку самолёта, выручку и риск того, что желающих окажется больше, чем мест.

Проект сделан для блока «Разработка» кейса «Динамическое ценообразование авиабилетов». Основной вариант **C** — веб-интерфейс с серверным API. Консольный скрипт для варианта **A** использует тот же код расчёта.

## Быстрый запуск

Понадобится **Node.js 22.13 или новее**. Для запуска и тестов рекомендую Node.js 24. Приложение хранит аккаунты, сессии и историю во встроенном SQLite.

```bash
npm ci
npm run build
npm start
```

Откройте [localhost:3000](http://localhost:3000), зарегистрируйтесь и попробуйте рейс **Москва → Сочи на 15 июня 2026 года** с ценой **9 500 ₽**.

Для разработки запустите `npm run dev` и откройте [localhost:5173](http://localhost:5173). Vite перенаправляет запросы к API на порт 3000.

## Как считается прогноз

Для каждого сценария спроса приложение берёт базовый спрос из CSV и пересчитывает его при выбранной цене. Медианный сценарий использует колонку `0.5_base_demand`.

```text
спрос = 0.5_base_demand − price_sensitivity × (цена − base_price)
продажи = min(seats, max(0, спрос))
```

График использует сценарии P10–P90 из стартового набора. Оценка риска нехватки мест строится интерполяцией между квантилями. Цена модели берётся из `0.5_price`, а при выходе за диапазон `price_min…price_max` интерфейс показывает предупреждение. Продажи и свободные места в сводке округляются до целых, дробные значения доступны в деталях расчёта.

Сервер и консольный скрипт используют общий [модуль прогноза](src/shared/forecast.ts).

### Консольный скрипт

```bash
npm run forecast -- --from Москва --to Сочи --date 15.06.2026 --price 9500 --chart
npm run forecast -- MOW AER 2026-06-15 9500 --json
npm run forecast -- --help
```

После сборки скрипт также можно запустить через `npm run forecast:built -- MOW AER 2026-06-15 9500`.

## Данные и размещение

В [`data/`](data/) лежат стартовые CSV с пятью маршрутами и 155 записями прогноза. `routes.csv` описывает направления и тарифы, `seasonal_forecast.csv` — даты, вместимость и сценарии спроса.

- Для своего прогноза замените файлы в `data/`, задайте папку через `DATA_DIR` или укажите пути через `FORECAST_PATH` и `ROUTES_PATH`. Сервер отслеживает изменения при запросах и перечитывает CSV без перезапуска. При ошибке чтения он продолжит использовать последнюю загруженную версию, если она есть.
- В файле прогноза обязательны `route`, `date`, `seats` и `0.5_base_demand`. Остальные квантили и связанные с ними колонки цен можно добавлять по мере необходимости. Поддерживаются CSV с запятой, точкой с запятой или табуляцией, BOM и даты в распространённых форматах, включая `2026-06-01` и `01.06.2026`.
- Для входа в раздел «Данные» задайте `INITIAL_ADMIN_EMAIL` и `INITIAL_ADMIN_PASSWORD` перед запуском. Сервер создаёт владельца, если в базе ещё нет администратора. Регистрация через форму создаёт обычные аккаунты.

[Инструкция по размещению](DEPLOY.md) описывает переменные окружения, запуск на Amvera, в Docker и на VPS. На хостинге подключите постоянное хранилище для базы и загружаемых CSV.

## API

Для прогноза нужна сессия, которую сервер выдаёт при входе или регистрации. Тело запроса `POST /api/forecast` передаётся в JSON.

```json
{
  "from": "MOW",
  "to": "AER",
  "date": "2026-06-01",
  "price": 9500
}
```

В этом примере медианный спрос и продажи составляют **704,5** билета при **900** местах. Ответ также содержит сценарии и оценку риска. Города можно передавать кодом или названием.

| Возможность | Маршруты API |
| --- | --- |
| Состояние сервиса | `GET /api/health` |
| Регистрация и сессия | `GET /api/auth/config`, `GET /api/auth/me`, `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout` |
| Направления, даты и цены модели | `GET /api/meta` |
| Прогноз, кривая цены, календарь и табло | `POST /api/forecast`, `POST /api/forecast/curve`, `POST /api/forecast/month`, `POST /api/forecast/board` |
| История | `GET` и `POST /api/history`, `PATCH` и `DELETE /api/history/:id`, `DELETE /api/history` с `mode=all` или `mode=unpinned` |
| CSV, только для администратора | `GET /api/admin/data`, `GET /api/admin/download/:kind`, `POST /api/admin/upload`, `POST /api/admin/restore` |

Скачивание возвращает CSV. Изменяющие запросы требуют `Content-Type: application/json`. При наличии заголовка `Origin` сервер сверяет его хост с хостом запроса. Пароли хешируются через scrypt, в SQLite хранится хеш токена сессии, а браузер получает cookie с флагом `HttpOnly`.

Реализация и параметры запросов описаны в [коде маршрутов API](src/server/routes.ts).

## Проверки

```bash
npx playwright install chromium
npm run test:all
```

`npm run test:all` запускает проверку типов, Vitest, сборку и Playwright в настольном и мобильном профилях Chromium. По отдельности доступны `npm run typecheck`, `npm test` и `npm run test:e2e`. Для отдельного браузерного прогона сначала выполните `npm run build`.

- **Vitest** проверяет формулу прогноза, граничные случаи, CSV, API, сессии и права доступа. Эталонные результаты для всех 155 записей рассчитаны на Python. Для проверки их повторной генерации нужны Python 3 и pandas. Проверить окружение можно командой `node scripts/check-golden-env.mjs`.
- **Playwright** проверяет регистрацию и вход, расчёт и сравнение цен, загрузку данных, навигацию и доступность через axe. Сервер использует отдельную базу и временную копию CSV. Дополнительный набор покрывает Firefox, WebKit и Chromium, включая проверки касаний, сетевых сбоев и внешнего вида.

Чтобы запустить дополнительный набор, установите браузеры командой `npx playwright install chromium firefox webkit` и выполните `npx playwright test -c playwright.extra.config.ts`. Для первого визуального прогона добавьте `--update-snapshots`. Эталонные снимки создаются для конкретной ОС и браузера.

При проверке публикации прошли сборка, проверка типов и **627 тестов Vitest**. В первом полном прогоне Chromium прошли **250 из 260** сценариев. После исправления зависимости от локальных обратных рейсов все **34 сценария** в двух затронутых наборах прошли повторно на обоих профилях.
