Решись Авиа — веб-приложение для прогноза продаж авиабилетов. Менеджер выбирает города, дату и цену билета, а приложение показывает ожидаемый спрос, загрузку самолёта, выручку и риск того, что желающих окажется больше, чем мест.

Проект сделан для блока «Разработка» кейса «Динамическое ценообразование авиабилетов». Реализован вариант **C** — веб-интерфейс с серверным API.

## Быстрый запуск на своём компьютере

Для запуска подойдёт **Node.js 24**.

```bash
npm ci
npm run build
npm start
```

После запуска откройте [localhost:3000](http://localhost:3000).

## Как владелец обновляет данные

**Прогноз и справочник маршрутов можно менять прямо на работающем сайте.** В разделе **«Данные»** можно скачать текущие CSV. Там же можно загрузить на сервер новые. Сайт проверит файл, покажет разницу с текущей версией и предупреждения, если что-то не так. Изменения вступят в силу только после нажатия **«Заменить файл»**. Следующий расчёт будет использовать новые данные без перезапуска сайта. Кнопка **«Вернуть предыдущую версию»** откатывает выбранный файл.

Email и пароль владельца задаются в настройках **Amvera → Переменные** на этапе **«Запуск»**. Регистрация через форму сайта создаёт обычный аккаунт. [Инструкция по размещению](DEPLOY.md#amvera-cloud)

## CSV с обратными рейсами для теста интерфейса

В стартовом наборе из условия задания пять маршрутов из Москвы и 155 рейсов. Моя тестовая пара сохраняет эти строки и еще добавляет **три обратных направления и девять рейсов на отдельные даты**. Вместимость, спрос и тарифы для добавленных рейсов заданы мной произвольно — они добавлены для более полной проверки интерфейса.

Пожалуйста, зайдите с админ аккаунта *(почта и пароль для аккаунта владельца лежат в файле Кривошеев_Сергей_Алексеевич_блок3.txt в моей папке на гугл диске под ссылками на гитхаб и сайт)* и протестируйте возможности замены csv файлов и то как классно интерфейс работает даже с более широкими данными.

| Файл | Что внутри |
| --- | --- |
| [`routes_test.csv`](data/routes_test.csv) | 8 направлений с тарифами, включая Сочи → Москва, Санкт-Петербург → Москва и Калининград → Москва. |
| [`seasonal_forecast_test.csv`](data/seasonal_forecast_test.csv) | 164 рейса с вместимостью и сценариями спроса P10–P90. У обратных рейсов 2–4 даты на направление. |

Для демонстрации в разделе **«Данные»** сначала загрузите `routes_test.csv` как **справочник маршрутов**, затем `seasonal_forecast_test.csv` как **файл прогноза**. Для каждого файла нажимайте **«Заменить файл»**. До загрузки прогноза у новых направлений будет статус «Прогноз для этого маршрута пока не загружен».

- **1 июня, Москва → Сочи.** Кнопка смены направления доступна. После разворота меняются вместимость и прогноз.
- **2 июня, тот же маршрут.** Обратного рейса на эту дату нет. Кнопка разворота недоступна, а на «Табло» обратного рейса нет.
- **7 июня на «Табло».** Видны два обратных рейса, из Сочи и Калининграда. На других датах список меняется.

Чтобы вернуть данные, которые были до демонстрации, сначала восстановите предыдущую версию прогноза, затем справочника. Чтобы загрузить набор из задания напрямую, используйте стартовые [`seasonal_forecast.csv`](data/seasonal_forecast.csv) и [`routes.csv`](data/routes.csv) в том же порядке.

## Как считается прогноз

Для каждого сценария спрос меняется пропорционально разнице между введённой и базовой ценой. Коэффициент чувствительности берётся из справочника маршрутов. Продажи ограничены вместимостью самолёта, а в сводке показываются целые билеты. [Код расчёта](src/shared/forecast.ts)

### Консольный скрипт

```bash
npm run forecast -- MOW AER 2026-06-01 9500 --chart
```
